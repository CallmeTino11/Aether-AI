### The important finding: raw `ts_rank` would have quietly broken grounding

DEC-0006's note requires re-calibrating any replacement retriever rather than swapping it in. Measured against the same clinic calibration set used for the reference retriever:

| Query | raw `ts_rank` | verdict at threshold 0.15 |
|---|---|---|
| "opening hours" (clear) | 0.187 | answers — but by 0.037 |
| "consultation cost" (decent) | 0.168 | answers — by 0.018 |

Everything compressed into a narrow band barely above the threshold. Reusing `MIN_GROUNDING_SCORE` against it would have been **coincidence, not calibration** — one longer knowledge document would have pushed a legitimately-grounded answer under the line, silently converting correct answers into escalations. That failure would have looked like "the AI is being unhelpful," not like a bug.

Replaced with **query-term coverage, squared** (DEC-0010), measured on the same set:

| Query | score | behaviour |
|---|---|---|
| "what are your opening hours?" | 1.00 | answers |
| "how much does a consultation cost?" | 0.44 | answers |
| "opening hours on saturday" | 0.44 | answers — grounded partial, an improvement |
| "consultation with a specialist on a Saturday" | 0.11 | **escalates** |
| "do you offer helicopter transfers?" | 0.00 | **escalates** |

Same 0–1 scale as the reference retriever, wide margins on both sides. A minimum-separation assertion is in the test suite so eroding the margin fails CI.

### Applied the DEC-0008 lesson pre-emptively

Integration tests skip locally without `DATABASE_URL` — convenient, but a misconfigured URL in CI would have left 8 tests silently skipped and the job green. Added `REQUIRE_INTEGRATION=1` for CI, which makes a missing database a hard error. Verified in all three states: guard on without DB fails, guard off skips cleanly, both set runs 8/8 (DEC-0011).
