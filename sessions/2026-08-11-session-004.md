## Work Completed

Checked GitHub Actions run status via the API and found **CI red on `d505d29`** — the session 003 commit. Two independent defects were behind it.

### Defect 1 — Node-version-dependent test invocation (the CI failure)

`npm test` used `node --test "dist/__tests__/**/*.test.js"`. The quoted glob is resolved by *Node's* glob engine, which exists on Node 22 (local) but not Node 20 (CI runner). Tests therefore passed locally and failed in CI.

Verified locally by comparing three invocation variants:

| Variant | Node 22 result |
|---|---|
| quoted glob (what CI ran) | passes — Node's glob engine handles it |
| unquoted shell glob | passes — shell expands to real paths |
| directory argument | **fails** — Node executes the directory as a module |

Fix: unquoted shell glob, so the shell expands paths before Node sees them and no version-specific feature is involved. CI now also runs a **Node 20 + 22 matrix** (DEC-0009) so version-specific breakage surfaces in CI instead of depending on which version a developer happens to run.

### Defect 2 — A validator that could never fail (worse than the first)

While auditing the workflows that *passed*, the link checker in `repository-validation.yml` turned out to be structurally incapable of failing:

```bash
grep ... | while read -r link; do
  fail=1        # assigned inside a pipeline subshell
done
exit $fail      # parent's $fail is still 0
```

Proven by injecting a broken link: the job printed `::error::` lines **and exited 0**. CI had been green on that basis for three commits.

Fix: validation logic moved out of YAML into `scripts/validate_repo.py` and `scripts/validate_decisions.py`, plus `scripts/test_validators.sh` — 9 self-tests (2 positive, 7 negative) that deliberately break something and assert a non-zero exit (DEC-0008). The self-tests run *before* the validators in CI.

### Incidental find

The new validator immediately failed on the clean repo — it caught a **real broken link in `README.md`** left behind when my own earlier diagnostic test failed to restore its backup. The old checker would have passed it silently. Repaired.

## Lesson Recorded

Two failures with one shape: **a green check is a claim, not evidence.** Both defects survived because output was not verified — the first because I reported success without reading the CI result, the second because the check itself was never tested against a case it should reject. Hence DEC-0008: every validator must prove it can fail.
