## Objective

Build the heart of the AI Receptionist: knowledge grounding, the conversation engine, and the persistence schema.

## Work Completed

- **Knowledge layer** — `KnowledgeRetriever` port + working keyword retriever with hard tenant filtering. Grounding threshold calibrated empirically against real retrieval scores (0.67 clear match / 0.22 decent / 0.08 vague → escalate) rather than guessed.
- **Prompt layer** — versioned, provider-neutral prompt construction; grounding rules centralized and reviewable.
- **Receptionist engine** — one-turn orchestration: retrieve → prompt → complete → escalation policy → new state + audit record. No vendor, persistence, or channel coupling.
- **Schema** — 7 tables with AI audit columns on messages, RLS on every tenant-scoped table, integrity constraints on escalation and leads.
- **Verification** — 7 unit tests passing; migration executed against real Postgres 16; cross-tenant read returns 0 rows, cross-tenant write rejected by the database; invalid states (escalation without reason, lead without contact, invalid role) all rejected.
- CI upgraded to run typecheck + tests + migration application.
